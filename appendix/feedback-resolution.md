# Приложение В. Доработка по отзыву преподавателя

Исходный отзыв передан Ивановым после сдачи; указанная оценка — 7, из них 4 за основную часть.
Ниже приведены изменения документов, а не заявление о новой оценке или готовности приложения.

| Пункт доработки | Что изменено | Подтверждение |
|---|---|---|
| 1. Фактическая история LLM | Отложена по просьбе Иванова. Начатая выгрузка и карта связей сохранены как рабочие материалы; подготовка отдельного PDF и окончательная проверка не завершены. | Открытый пункт. |
| 2. История решений | РешениеПоРейсу связано с выполнением и автором. Попытки без смены статуса и повторные сроки сохраняются отдельными записями. | БП-13, модель 5.2, КП-05.13–КП-05.14, ЖР-14. |
| 3. Минимум две точки | 2..N показано в таблице, PDF и SVG для точек маршрута и планового рейса. Исходная Mermaid-схема также явно указывает минимум две. | БП-16, модель 5.1 и 5.3, КП-01.7, ЖР-15. |
| 4. Дедупликация | Разделены ключ исходного сообщения и номер доставки; определены повтор, конфликт, окно хранения и одновременная обработка. | БП-18, КП-03.5–КП-03.9, ЖР-16. |
| 5. Производные данные | Доля удалена из самостоятельных фактов выполнения. Определены источники положения, связи, прогноза и отчёта, пересчёт и контрольные снимки. | Модель 5.5, КП-07.6, приложение А, ЖР-17. |
| 6. Снимок расписания | Рабочая копия создаётся с заданием, до выпуска обновляется только явно с проверкой конфликтов; окончательно фиксируется при первом выпуске. | БП-16, БС-01–БС-02, КП-01.5–КП-01.6, ЖР-18. |
| 7. История установки | Добавлены устройство и периоды установки; позднее сообщение сохраняет прежнюю принадлежность. | БП-19, КП-01.8, КП-03.7, ЖР-19. |
| 8. Нагрузка и восстановление | Рассчитаны 100/300 автобусов, интервалы 5/10/30 с, сырые объёмы, повторы, реестр ключей и сроки. Восстановление не зависит только от последних трёх минут. | Приложение А, НФТ-01–НФТ-05, ЖР-20. |
| 9. PostgreSQL | Подготовлены частичные уникальные и исключающие ограничения, порядок блокировок и транзакций. SQL-фрагмент проверен отдельно. | Приложение Б, planning/, отчёт проверки. |
| 10. Сохранность бизнес-фактов | Прохождения, результаты, решения и отклонения сохраняются в PostgreSQL; Redis содержит восстанавливаемые копии. Описан сбой между хранилищами. | Приложение А.4–А.5, НФТ-04–НФТ-05. |

Практически выполнены структурные проверки документов, проверка расчётов и запуск изолированного
SQL-фрагмента на PostgreSQL 14.23: семь ожидаемых конфликтов, соприкосновение интервалов,
откат неудачной подмены и сохранение истории при успешной. Временный сервер остановлен.
Это проверка ограничений, не полной реализации транзакционных функций. Версию PostgreSQL
учебного приложения нужно закрепить и повторить проверки на ней при создании стенда.

Следующий спринт: реализовать операции и двухклиентские проверки из Б.5, измерить реальную
нагрузку и восстановление из А.5. Сроки 60 секунд и 5 минут являются целями. Отсутствующие
ранние фрагменты LLM по-прежнему не могут быть предъявлены как фактическая переписка.
