# КТ-04 · Runbook

Все команды выполняются из корня репозитория. Используйте тот же `KT04_SECRETS_DIR`, который был задан при инициализации.

```sh
dc() { docker compose -f deploy/kt04/compose.yaml -p transport-kt04 "$@"; }
dc ps
dc logs --tail 80 primary replica
```

## Недоступен узел

| Признак | Действие | Проверка после запуска |
| --- | --- | --- |
| Replica недоступна, primary отвечает | Проверьте логи replica и WAL sender на primary. Если контейнер остановлен, выполните `dc start replica`. | На replica `pg_is_in_recovery()` возвращает `true`. WAL receiver принимает данные, позиция replay догоняет контрольный LSN primary. |
| Primary недоступен, клиент получает ошибку подключения | Проверьте контейнер и его логи. Если контейнер остановлен, выполните `dc start primary`. Пока primary недоступен, на replica доступно чтение уже применённых данных. | Primary принимает соединения и запись, replica снова догоняет WAL. Стенд сохраняет исходные роли узлов. |
| Клиент потерял связь во время выпуска наряда | После восстановления связи проверьте UUID в `transport.operation_request` или повторите выпуск с исходным UUID и параметрами. | Для UUID существует одна запись запроса, в аудите один переход `planned → on_line`. |

Служебные команды проверки узлов:

```sh
dc exec -T -u postgres primary psql -X -d transport_kt04 -c   'SELECT pg_current_wal_lsn(); SELECT application_name,state,replay_lsn FROM pg_stat_replication; SELECT transport.check_model();'
dc exec -T -u postgres replica psql -X -d transport_kt04 -c   'SELECT pg_is_in_recovery(),pg_last_wal_replay_lsn(); SELECT status,sender_host FROM pg_stat_wal_receiver;'
```

## Ошибка TLS или авторизации

Если сертификат отклонён, проверьте CA из текущего каталога секретов и имя сервера в строке подключения. С хоста используйте `localhost` или `127.0.0.1`, внутри Compose — имя сервиса. Для проверки соединения передайте `sslmode=verify-full` и `sslrootcert` с путём к `ca.crt`. При отказе SCRAM проверьте роль, базу, порт, соответствующую строку в `pgpass` и права файла `0600`. Отказ с `42501` означает, что аутентификация состоялась и операция запрещена правами PostgreSQL. [Правила подключений](../../deploy/kt04/pg_hba.conf)

## Отставание реплики и место под WAL

Проверьте `pg_stat_replication`, `pg_replication_slots` и `pg_stat_archiver` на primary. При росте отставания смотрите разницу между текущим LSN и `replay_lsn`, время последней успешной архивации и свободное место в томах данных и архива. Восстановите доступность replica или запись в архив. Если слот потерял необходимый WAL, для реплики нужна новая физическая базовая копия. Оставьте текущие тома и журналы для диагностики.

## Восстановление данных

Внутри этапа `backup` используются следующие команды PostgreSQL (на чистом экземпляре сначала создаются роли без паролей, затем пароли задаются из внешних файлов):

```sh
pg_dump -Fc -d transport_kt04 > transport.dump
pg_dumpall --roles-only --no-role-passwords > roles.sql
pg_restore --exit-on-error --create -d postgres transport.dump
```

Это пояснение выполняемых операций. Готовая команда `./bin/kt04 backup` сама выбирает отдельные source/restore, внешний каталог и проверяет результат. Нельзя направлять restore в primary. Файлы секретов и дамп имеют права `0600`, внешний каталог — `0700`; их не включают в Git и архив сдачи.

- **Логический дамп.** `./bin/kt04 backup` создаёт копию и восстанавливает её в отдельный чистый `restore`. Сравните снимки исходной и восстановленной баз в отчёте. Проверьте владельцев и права, успешный вход рабочих ролей, ограничения и результат `transport.check_model()`.
- **Ошибка данных с известным моментом.** Зафиксируйте целевую точку перед ошибочной транзакцией и проверьте, что базовая копия и WAL покрывают этот интервал. `./bin/kt04 pitr` воспроизводит учебный случай на отдельном экземпляре `pitr`. Для учебной точки проверьте наличие маркера до цели, отсутствие маркера после неё и целостность модели. Рабочая база продолжает обслуживаться primary.

Журналы экземпляров восстановления доступны через `dc --profile restore --profile pitr logs --tail 80 restore pitr`. Сопоставьте результат с [артефактами прогона](../../artifacts/kt04/).
