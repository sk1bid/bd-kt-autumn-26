## Владение и журнал архитектурных решений

1. PostgreSQL отвечает за маршрут, расписание, выпуск, установки устройств, телеметрию и результат её приёма. MongoDB отвечает за процедуру диагностики, классификатор симптомов и историю осмотров. Внешний deviceId соответствует transport.device.id. MongoDB проверяет положительный тип long, для проверки существования оборудования требуется обращение к PostgreSQL. Межбазового внешнего ключа нет.
2. Одна процедура (procedures) применяется во многих осмотрах (inspections). Инженер читает акт целиком. В findings встроены название выполненного шага, результат и ссылки на симптомы. Снимок названия сохраняет смысл старого акта при редактировании процедуры. Поля отдельных осмотров могут различаться, например примечание к антенне.
3. Между осмотрами и симптомами связь M:N. Один осмотр фиксирует несколько симптомов, один симптом встречается во многих осмотрах. symptomIds ссылаются на symptoms по ObjectId. Уточнение названия симптома требует изменения одного справочного документа. Для истории конкретного устройства растёт число актов, каждый акт хранится отдельно.
4. Осмотр содержит от 1 до 32 результатов, у каждого результата допустимы pass или fault и максимум восемь различных ссылок на симптомы. Валидатор проверяет дату осмотра, типы ссылок и наличие обязательных полей. Учебный сценарий сначала создаёт объекты справочников, затем ссылающийся акт и удаляет их в обратном порядке. Для каждого запуска используются новые ObjectId.

Для существующего стенда задайте KT04_SECRETS_DIR равным каталогу его секретов. Из корня проекта выполнить `make kt04-proxy kt05-sql kt05-mongo`. Требуются работающие primary и standby КТ-04 с учебной базой. MongoDB запускается отдельным проектом Compose без публикации порта на хост.

Архив КТ-05 содержит каталог и самостоятельную демонстрацию MongoDB. После распаковки MongoDB можно проверить двумя командами:

```sh
docker compose -f deploy/kt05/compose.yaml up -d --wait
docker compose -f deploy/kt05/compose.yaml exec -T mongo mongosh --quiet /examples/crud.js
```

Для выполнения SQL через любой psql с доступом на чтение к базе проекта укажите параметры подключения через libpq и запустите:

```sh
psql -X -v ON_ERROR_STOP=1 -v period_start='2026-09-22 00:00+07' -v period_end='2026-09-24 00:00+07' -v min_late=1 -v limit=10 -v device_id=1 -f sql/kt05/catalog.sql
```
