# Как менять формат акта осмотра

Текущую форму inspections считаем версией 1. Созданные акты не содержат schemaVersion. Например, сегодня идентификатор прибора хранится в deviceId. Если понадобится поддержать несколько источников оборудования, в версии 2 его можно представить объектом device с полями source и id. Ниже описан порядок такого перехода.

1. Сначала обновить чтение. Отсутствие schemaVersion означает v1: взять deviceId и считать источником transport.device. При schemaVersion равном BSON int 2 взять device.source и device.id. Неизвестную явную версию вернуть как ошибку формата с идентификатором акта. На этом этапе писатель продолжает создавать v1.
2. Перед включением записи v2 расширить валидатор inspections двумя взаимоисключающими ветками. В v1 обязательны deviceId типа long от 1 и отсутствие schemaVersion. В v2 обязательны schemaVersion типа int со значением 2 и device с полями source (на первом этапе только transport.device) и id (long от 1). В v2 запретить старое deviceId, чтобы у акта был один идентификатор прибора. Общие ограничения для findings, procedureId и observedAt сохраняются.
3. Проверить старый и новый акт для одного устройства. При чтении должны совпасть идентификатор оборудования, время, шаги и симптомы. Для выборки истории по прибору на переходный период искать по обеим формам. До включения писателя отдельно проверить отказ для версии 3 и для документа v2 без device.id.
4. После обновления всех читателей включить создание v2. Старые акты можно оставить в исторической форме. Обновление примечания в старом акте сохраняет его текущую форму. При проблеме вернуть писатель на v1, сохранив чтение обеих форм для уже записанных v2.
5. Убирать поддержку v1 можно после проверки отсутствия документов и писателей v1 и после решения о том, как будут читаться восстановленные архивы. Справочники procedures и symptoms изменяются независимо: смена формы акта не требует переписывать справочные документы.
